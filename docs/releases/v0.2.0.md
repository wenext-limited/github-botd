# github-botd v0.2.0

Machine-user clients may opt into `all_repositories` and address canonical
`owner/repo` targets without alias entries. Capabilities remain independent,
queued actions recheck current grants, and canonical writes pin GitHub's
immutable repository ID. Legacy aliases and installation routing remain valid.

The new `pull.merge` capability supports guarded exact-head Squash merges.
The trusted native client supplies verified requester and clean-review
attestations. The daemon independently verifies current author/assignee role,
repository identity, head/base, conflicts, outstanding change requests and
trusted compilation before writing. GitHub Actions proof also identifies its
actual successful workflow run and unchanged trusted workflow blob.

`POST /v1/merge-check` is read-only. Queued, dry-run, failed and uncertain
outcomes remain distinct; ambiguous writes are not retried. No admin bypass,
force push, branch deletion, approval verdict or arbitrary API proxy is added.

Upgrade this daemon before iBot v0.27.0. Enable the new grants and verified
CI/identity configuration deliberately. Verification uses local fake GitHub
HTTP services and the offline demo, never a real PR merge.
